## ۱. ✦ معرفی

**POMP NET MOHAMMAD** هویت اصلی و نام برند این پروژه است. **SUPER JINX** نام محصول/نسخه پنل است و در سلسله‌مراتب بصری زیر نام برند قرار می‌گیرد.

این مخزن یک بسته سفارشی‌سازی و استقرار برای پنل مبتنی بر **Marzban** است. اجزای آن شامل رابط اختصاصی پمپ‌نت، تنظیمات Nginx و Caddy، پیکربندی Xray، صفحه اشتراک، ابزارهای API جانبی، ابزارهای نگهداری، Docker و گردش‌کار CI است.

## ۳. ⚡ قابلیت‌های موجود در سورس

### ۳.۱ داشبورد مستقل POMP NET

فایل `pompnet-dashboard.html` رابط مستقل فارسی را در کنار داشبورد اصلی Marzban ارائه می‌کند.

| بخش رابط | قابلیت | پیاده‌سازی / رفتار |
|---|---|---|
| ورود | ورود مدیر با نام کاربری و رمز | احراز هویت از endpoint ورود Marzban |
| نشست | نگهداری توکن ورود | `sessionStorage` مرورگر |
| نمای کلی | آمار کاربران | تعداد کل و کاربران فعال |
| ترافیک | جمع‌بندی مصرف و سقف ترافیک | محاسبه از اطلاعات کاربران |
| کاربران | فهرست و جست‌وجو | جست‌وجو بر اساس نام کاربری |
| ساخت کاربر | نام، حجم، اعتبار و سیاست ریست | ارسال درخواست ساخت به API |
| پروتکل | انتخاب نوع اتصال | VLESS، VMess و Trojan |
| حذف کاربر | حذف با تأیید مدیر | درخواست حذف به API |
| وضعیت سیستم | نمایش وضعیت سرویس | متکی به endpointهای وضعیت موجود |
| پشتیبانی | ارتباط تلگرام | [@NovaTunneli](https://t.me/NovaTunneli) |
| نمایشگر | چیدمان واکنش‌گرا | موبایل و نمایشگر بزرگ‌تر |

> **مرز قابلیت:** داشبورد مستقل فعلی شامل «نمای کلی»، «کاربران»، «ساخت کاربر» و «وضعیت سیستم» است. مدیریت پیشرفته نمایندگان در سرویس جانبی `jinx_api.py` قرار دارد؛ بنابراین تا زمانی که رابط گرافیکی آن جداگانه اضافه و آزمایش نشده، آن را صفحه کامل داخل داشبورد معرفی نمی‌کنیم.

### ۳.۲ هسته مدیریت و Xray

| جزء | نقش در پروژه | فایل / مسیر |
|---|---|---|
| Marzban | هسته مدیریت پنل و کاربران | image پایه `gozargah/marzban:latest` |

| SQLite | ذخیره داده پنل | `/var/lib/marzban/db.sqlite3` |
| پیکربندی Xray | تعریف inbound و outbound | `xray_config.json` |
| inbound محافظت‌شده | تنظیمات inbound کمکی | `locked_inbound.json` |
| اعتبارسنجی Xray | بازسازی و بررسی سازگاری تنظیمات | `lock.py` |

گزینه‌های اختیاری فقط در صورت سازگاری با نسخه Xray/Marzban وارد پیکربندی نهایی می‌شوند؛ وجود نام یک گزینه در تنظیمات به معنی فعال‌بودن قطعی آن نیست.

### ۳.۳ سرویس جانبی Jinx API

سرویس `jinx_api.py` روی `127.0.0.1:8090` اجرا می‌شود و از مسیر `/jinx-api/` در Nginx در دسترس قرار می‌گیرد.

| حوزه | عملیات موجود در کد | جزئیات |
|---|---|---|
| حساب مدیر | تغییر نام کاربری و رمز | بررسی اعتبارنامه فعلی و اعمال تراکنشی |
| نشست مدیر | دریافت توکن تازه | پس از تغییر اطلاعات حساب |
| محافظت ورود | محدودسازی تلاش ناموفق | endpoint وضعیت قفل ورود |
| QR | تولید QR با خروجی SVG | در صورت نصب بودن Segno |
| نمایندگان | ایجاد، فهرست، ویرایش و حذف | برای مدیر دارای دسترسی sudo |
| سهمیه نماینده | محدودیت تعداد کاربر و ترافیک | همراه زمان انقضا |
| وضعیت نماینده | فعال‌سازی و غیرفعال‌سازی | بستن نشست‌ها هنگام غیرفعال‌سازی |
| سوابق | ثبت شارژ و تاریخچه | اطلاعات مربوط به هر نماینده |
| کنترل دسترسی | بررسی درخواست‌های نوشتنی | اعمال محدودیت در لایه واسط API |

**مدل دسترسی:** نماینده در این سرویس یک مدیر عادی و غیر sudo در Marzban است. محدودسازی کاربران متعلق به هر نماینده در لایه واسط API اعمال می‌شود. وجود API به‌تنهایی به معنی وجود صفحه گرافیکی کامل نمایندگان در داشبورد مستقل نیست.

## ۷. 🔌 پروتکل‌ها و انتقال‌ها

### پیکربندی پایه مخزن

فایل `xray_config.json` در حال حاضر سه inbound پایه WebSocket دارد:

| نام inbound | پروتکل | شبکه انتقال | پورت داخلی پایه |
|---|---|---|---:|
| VLESS WS | VLESS | WebSocket | 2001 |
| VMESS WS | VMess | WebSocket | 2002 |
| TROJAN WS | Trojan | WebSocket | 2003 |

این inboundها روی loopback یعنی `127.0.0.1` گوش می‌دهند و از طریق Nginx مسیردهی می‌شوند. پورت‌های داخلی را نباید بدون بررسی پیکربندی Nginx و Xray به اینترنت باز کرد.

`lock.py` می‌تواند بر اساس نسخه Xray/Marzban و متغیرهای محیطی، گزینه‌ها یا inboundهای سازگار دیگری را اضافه کند؛ این موضوع به معنی فعال‌بودن همیشگی همه انتقال‌ها نیست. Reality، XHTTP، HTTPUpgrade، BBR، TFO، Mux و قابلیت‌های اختیاری فقط در شرایط پشتیبانی نسخه، تنظیم محیطی و پذیرش پیکربندی نهایی قابل استفاده‌اند.

داشبورد مستقل فعلی در فرم ساخت کاربر سه انتخاب VLESS، VMess و Trojan را ارائه می‌دهد. پیکربندی پایه مخزن یک سرور/یک مقصد اجرایی را هدف می‌گیرد و سه inbound واقعی WebSocket را تعریف می‌کند؛ این سه گزینه به معنی سه کشور یا سه لوکیشن نیستند. هر پروفایل/لینک باید از inbound فعال و تنظیمات همان سرور ساخته شود؛ صرفاً تغییر نام یا تکثیر متن لینک، کانفیگ مستقل و قابل اتصال ایجاد نمی‌کند. نام نمایشی اشتراک با برند `POMP NET MOHAMMAD — SUPER JINX` تنظیم شده است.

## ۸. 🚀 نصب روی VPS

### پیش‌نیازها

1. VPS لینوکسی با دسترسی root.
2. Docker Engine و Docker Compose plugin.
3. Git، OpenSSL، Python 3، curl و ابزار `ss`.
4. دامنه‌ای که DNS آن به IP سرور اشاره کند.
5. پورت‌های TCP/80، TCP/443 و TCP/2096 آزاد و قابل دسترسی از اینترنت.
6. ساعت صحیح سیستم و Volume پایدار برای داده‌ها.
7. اطمینان از اینکه ارائه‌دهنده VPS استفاده موردنظر را مجاز می‌داند.

### نصب اولیه

اسکریپت نصب، مخزن را در `/opt/pompnet-super-jinx` دریافت می‌کند، دامنه و نام مدیر را می‌گیرد، رمز تصادفی می‌سازد و فایل `.env` را با مجوز محدود ایجاد می‌کند.

```bash
git clone https://github.com/uxurx7rh7e7xr73uue73e8/POMP-NET-MOHAMMAD-SUPER-JINX.git /opt/pompnet-super-jinx
cd /opt/pompnet-super-jinx
sudo bash setup-vps.sh
```

اگر با کاربر root وارد شده‌ای، `sudo` لازم نیست.

### رفتار محافظتی اسکریپت نصب

- فقط با دسترسی root اجرا می‌شود.
- وجود Docker، Compose، Git، OpenSSL، Python، `ss` و curl را بررسی می‌کند.
- اگر پوشه پروژه از قبل مخزن Git باشد، فقط `git pull --ff-only` را اجرا می‌کند.
- اگر پوشه مقصد متعلق به پروژه دیگری باشد، متوقف می‌شود.
- اگر فایل `.env` موجود باشد، آن را بازنویسی نمی‌کند.
- اگر Volume با نام `pompnet_data` موجود باشد، برای جلوگیری از ساخت اعتبارنامه جدید روی داده قدیمی متوقف می‌شود.
- پورت‌های TCP/80 و TCP/443 را بررسی می‌کند.
- رمز تصادفی مدیر را فقط در فایل محلی `.env` با مجوز 600 نگه می‌دارد.
- Compose را اعتبارسنجی و image را build می‌کند.
- در پایان، سلامت HTTPS را بررسی می‌کند.

آدرس رابط اختصاصی پمپ‌نت:

`https://YOUR-DOMAIN/panel/`

داشبورد اصلی Marzban نیز از مسیر زیر باقی می‌ماند:

`https://YOUR-DOMAIN/dashboard/`

آدرس اشتراک با توجه به شناسه اشتراک و پیکربندی prefix ساخته می‌شود؛ در مسیر Compose، TLS پورت 2096 در نظر گرفته شده است.

## ۹. 🔄 به‌روزرسانی امن

قبل از به‌روزرسانی، از Volume و فایل `.env` نسخه پشتیبان امن بگیر. سپس:

```bash
cd /opt/pompnet-super-jinx
git pull --ff-only
docker compose up -d --build
docker compose ps
docker compose logs --tail=150
```

**هرگز برای به‌روزرسانی عادی از `docker compose down -v` استفاده نکن.** گزینه `-v` می‌تواند Volume داده را حذف کند. همچنین پوشه `/var/lib/marzban` و فایل `.env` را برای رفع خطای معمولی حذف نکن.
اگر نصب قبلی با همین مخزن و Volume انجام شده است، قبل از اجرای دوباره اسکریپت نصب اولیه، راهنمای `DEPLOY-VPS.md` را بخوان؛ اسکریپت عمداً در صورت مشاهده `.env` یا Volume موجود متوقف می‌شود.

## ۱۱. 🔐 امنیت و مدیریت رمز

- نام کاربری مدیر اصلی در همه نصب‌ها **`ADMIN_tanel9990`** است و حساب با `is_sudo=True` در دیتابیس واقعی Marzban ایجاد/ارتقا داده می‌شود.
- اگر `ADMIN_PASSWORD` را در Secret/Variables خصوصی تنظیم کنی، همان رمز برای همان نصب استفاده می‌شود؛ در غیر این صورت در اولین راه‌اندازی یک رمز قوی و یکتا تولید می‌شود، روی Volume پایدار با مجوز محدود نگه‌داری می‌شود و فقط یک بار در لاگ راه‌اندازی با برچسب `ONE-TIME LOGIN` نمایش داده می‌شود. رمز را در سورس یا GitHub commit نکن.
- رمز باید حداقل ۱۴ نویسه داشته باشد. برای تغییر رمز مدیر موجود از Secret، `RESET_ADMIN_PASSWORD=1` را فقط برای یک بار راه‌اندازی تنظیم کن و سپس آن متغیر را حذف کن.
- رمز در دیتابیس به‌صورت bcrypt hash ذخیره می‌شود. پس از راه‌اندازی اولیه، restart عادی رمز مدیر را بازنویسی نمی‌کند؛ رمز تغییرکرده از داخل پنل نیز حفظ می‌شود.
- برای ماندگاری رمز تولیدشده، Volume مسیر `/var/lib/marzban` باید در پلتفرم Deploy پایدار باشد. در Railway، `ADMIN_PASSWORD` را در Variables خصوصی بگذار یا Volume پایدار را به `/var/lib/marzban` متصل کن و رمز یک‌باره را از لاگ اولین Deploy بردار.
- فایل `.env` شامل رمز مدیر است و نباید commit یا منتشر شود؛ اسکریپت VPS آن را با مجوز 600 ایجاد می‌کند.
- داشبورد اختصاصی و داشبورد اصلی Marzban از حساب مدیر همان هسته استفاده می‌کنند؛ بنابراین اعتبارنامه مدیر برای هر دو مسیر پنل یکسان است. سرویس‌های جانبی یا استقرارهای جداگانه فقط در صورتی همین رمز را خواهند داشت که Secret مشابه برای آن محیط هم تنظیم و اعمال شود.
- توکن داشبورد اختصاصی در `sessionStorage` مرورگر نگه‌داری می‌شود و با بستن session از بین می‌رود.
- سرویس Jinx API روی loopback داخلی اجرا می‌شود و از Nginx مسیردهی می‌شود.
- محدودیت تلاش ورود در سرویس جانبی پیاده‌سازی شده است.
- نسخه پشتیبان پایگاه داده و فایل‌های تنظیمات شامل اطلاعات حساس است؛ آن‌ها را رمزگذاری و خارج از دسترس عمومی نگه‌دار.

## ۱۷. مهاجرت هدفمند به PasarGuard

طرح اجرایی مستقل برای انتقال امن از Marzban به هسته رسمی PasarGuard، شامل پشتیبان‌گیری، نگاشت داده‌ها، inboundهای واقعی Xray، اشتراک TLS روی 2096، Cloudflare و آزمون v2rayNG در [راهنمای مهاجرت PasarGuard](docs/PASARGUARD-MIGRATION.md) ثبت شده است. **وضعیت فعلی: برنامه مهاجرت مستند شده؛ هسته و دیتابیس این شاخه هنوز Marzban هستند و مهاجرت واقعی تکمیل نشده است.**

همچنین راه‌اندازی مدیر دیگر رمز تصادفی تولید یا در log چاپ نمی‌کند؛ برای نصب اولیه باید Secret ثابت `ADMIN_PASSWORD` در محیط اجرا تنظیم شود. رمز موجود در دیتابیس پایدار، بدون reset صریح دست‌نخورده می‌ماند.
