# طرح مهاجرت امن POMP NET به هسته PasarGuard

## هدف نهایی

- برند و رابط فارسی: POMP NET MOHAMMAD با چیدمان RTL و حفظ رابط فعلی تا زمان جایگزینی کامل.
- هسته مدیریت: نصب مستقل و رسمی PasarGuard (نه کپی فایل‌های اختصاصی wrapper پروژه SuperJinX).
- موتور شبکه: Xray واقعی و inboundهای VLESS، VMess و Trojan.
- انتقال‌ها: WebSocket و HTTPUpgrade فقط در صورت پشتیبانی نسخه Xray نصب‌شده و اعتبارسنجی پیکربندی.
- اشتراک: endpoint اختصاصی با مسیرهای واقعی PasarGuard و TLS روی پورت عمومی 2096؛ پورت فقط پس از انتشار TCP/2096 و آزمون بیرونی قابل اعلام به‌عنوان فعال است.
- QR و لینک: خروجی مستقیم از subscription URI تولیدشده توسط هسته، قابل import در v2rayNG.
- Cloudflare: دامنه DNS پروکسی‌شده یا Cloudflare Tunnel؛ این دو روش جدا هستند و نباید hostname ساختگی تولید شود.
- داده‌ها: انتقال کاربران، رمزهای هش‌شده در صورت سازگاری، محدودیت حجم/زمان، وضعیت‌ها، inbounds و شناسه‌های اشتراک با گزارش تطبیق و امکان rollback.

## وضعیت فعلی واقعی

این شاخه هنوز بر پایه Marzban است:
- image پایه Docker: `gozargah/marzban:latest`
- دیتابیس فعلی: `/var/lib/marzban/db.sqlite3`
- API و مدل‌های اختصاصی کد فعلی به ماژول‌های Marzban وابسته‌اند.
- Volume فعلی `/var/lib/marzban` است؛ مسیر داده PasarGuard برابر `/var/lib/pasarguard` است.

بنابراین هسته هنوز مهاجرت نکرده و نباید این شاخه را PasarGuard فعال یا آماده اتصال واقعی معرفی کرد.

## مراحل اجباری مهاجرت

1. **قفل تغییرات و نسخه پشتیبان**
   - توقف عملیات نوشتن روی پنل قدیمی در پنجره مهاجرت.
   - تهیه نسخه پشتیبان سازگار از SQLite، فایل‌های Xray، فایل‌های جانبی و Volume.
   - ثبت checksum و آزمون بازیابی نسخه پشتیبان؛ صرفاً وجود فایل backup کافی نیست.

2. **استقرار موازی هسته رسمی**
   - ساخت image مستقل بر پایه نسخه رسمی PasarGuard و Xray سازگار.
   - استفاده از Volume جداگانه در `/var/lib/pasarguard`.
   - حفظ سرویس قدیمی Marzban بدون تغییر تا پایان آزمون.

3. **مبدل داده**
   - استخراج فقط از API/مدل‌های نسخه مشخص Marzban.
   - نگاشت username، hash رمز در صورت سازگاری الگوریتم، data_limit، expire، reset strategy، status و subscription identifiers.
   - ساخت گزارش موارد منتقل‌نشده؛ هیچ فیلدی نباید بی‌صدا حذف یا مقدار پیش‌فرض جعلی بگیرد.
   - عدم انتقال session/tokenهای موقت و کلیدهای داخلی ناسازگار.

4. **ساخت inbound و مسیر شبکه**
   - تعریف VLESS، VMess و Trojan با شناسه‌های یکتا و transportهای پشتیبانی‌شده.
   - هماهنگی دقیق path/host بین Xray و Nginx.
   - اجرای تست syntax و تست handshake واقعی از بیرون شبکه؛ تولید URI به‌تنهایی تست اتصال نیست.

5. **اشتراک و پورت 2096**
   - نگاشت endpoint اشتراک PasarGuard به Nginx.
   - انتشار TCP/2096 در میزبان/ارائه‌دهنده و TLS معتبر برای دامنه.
   - تست HTTP status، محتوای subscription و import در v2rayNG.
   - اگر پلتفرم مقصد TCP proxy یا پورت موردنیاز را ارائه نکند، از 443 استفاده شود و 2096 فعال اعلام نشود.

6. **Cloudflare**
   - انتخاب صریح DNS proxy یا Tunnel.
   - در حالت Tunnel، hostname و token فقط از Secretهای محیطی خوانده شوند.
   - بررسی WebSocket و محدودیت‌های پروکسی برای هر transport.
   - هیچ دامنه یا IP ساختگی در لینک‌ها قرار نگیرد.

7. **آزمون پذیرش و جابه‌جایی**
   - ورود مدیر، ایجاد/حذف کاربر آزمایشی، اعمال محدودیت، تمدید و revoke اشتراک.
   - تست URI و QR در v2rayNG و اتصال واقعی از یک شبکه بیرونی.
   - تطبیق تعداد کاربران و سهمیه‌ها با گزارش مهاجرت.
   - فقط پس از موفقیت همه آزمون‌ها تغییر ترافیک عمومی؛ نگهداری backup و مسیر rollback.

## رمز مدیر

رمز مدیر نباید به‌صورت تصادفی در زمان startup ساخته یا در log چاپ شود. مقدار ثابت انتخاب‌شده توسط مالک باید در Secret با نام `ADMIN_PASSWORD` تنظیم شود. برای نصب اولیه یا تغییر صریح رمز، `RESET_ADMIN_PASSWORD=1` فقط در همان استقرار موقتاً فعال شود و پس از موفقیت حذف گردد. رمز خام هرگز در Git ثبت نشود.

تغییرات این شاخه اکنون تولید خودکار رمز مدیر را متوقف کرده‌اند؛ اما مقدار Secret در Railway از این مخزن قابل تنظیم نیست. در دیتابیس موجود، hash فعلی حفظ می‌شود مگر اینکه مدیر reset صریح انجام دهد.

## محدودیت‌های تأیید

- دسترسی Railway فعلی Viewer است؛ بنابراین Volume، Variables، TCP proxy و deployment زنده از این اتصال قابل تغییر یا تأیید نیست.
- تا زمانی که مهاجرت موازی، انتقال داده، آزمون بیرونی و rollback انجام نشده، این سند نقشه اجرایی است، نه گواهی تکمیل مهاجرت.
- از کد اختصاصی wrapper پروژه SuperJinX با برند دیگر استفاده یا آن را بازنشر نمی‌کنیم؛ پیاده‌سازی باید مستقل و مطابق مجوز اجزای رسمی PasarGuard باشد.
